# Small Business Assistant (Ontario) - Phase 1: RAG baseline

A chatbot that answers small-business startup questions using an open-weight model running
**locally** through Ollama, grounded in official Ontario / Canada guidance with cited sources.
Nothing is trained yet. This is the baseline that Phase 2 (evaluation) and Phase 4 (fine-tuning)
will be measured against.

```
question -> embed -> Chroma vector search -> top passages -> local LLM (Ollama) -> answer + sources
```

## 1. One-time setup (macOS)

```bash
# 1. Install Ollama from https://ollama.com (or: brew install ollama), then start it
ollama serve            # skip if the desktop app is already running

# 2. Pull the models (about 2 GB + 0.3 GB)
ollama pull llama3.2:3b
ollama pull nomic-embed-text

# 3. Python environment
cd smallbiz-assistant
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Memory guide: 8 GB Mac -> keep `llama3.2:3b`. 16 GB+ -> try `CHAT_MODEL=llama3.1:8b` or
`CHAT_MODEL=qwen2.5:7b` (run `ollama pull <name>` first).

## 2. Build the knowledge base

```bash
python fetch_sources.py     # downloads the pages listed in sources.yaml into data/web/
python ingest.py            # chunks + embeds everything into chroma_db/
```

Check `data/web/` afterwards and open a file or two. If a page's text looks wrong or the
fetcher reports "FAIL" for some URLs (government sites move pages), fix or remove the URL in
`sources.yaml`, or save the text yourself as a `.md` / `.txt` / `.pdf` file in `data/my_docs/`.
Anything in `data/my_docs/` is ingested too (a short sample guide is already there).

## 3. Ask questions

```bash
python ask.py "How do I register a business name in Ontario?"   # command line
python app.py                                                   # chat UI at http://127.0.0.1:7860
```

Every answer ends with the sources it drew on. If nothing scores above `MIN_SIMILARITY`, the
assistant first checks whether the question is about small business at all: if not, it politely
declines; if so, it answers in general terms and says it has no official source.

## Files

| File | Purpose |
|---|---|
| `sources.yaml` | URLs to fetch, each tagged with its reuse licence |
| `fetch_sources.py` | Downloads pages, keeps the main text, saves Markdown with a citation header |
| `chunking.py` | Loads .md/.txt/.pdf, splits by heading and size with overlap |
| `embeddings.py` | Text -> vectors via Ollama (`nomic-embed-text`) |
| `ingest.py` | Builds the Chroma vector database |
| `rag.py` | Retrieval (embeddings + keyword search), similarity cut-off, scope check, whole-page sources, prompt assembly, streaming answer |
| `lexical.py` | Keyword search on rare words (finds names like "Starter Company Plus" that embeddings miss) |
| `prompts.py` | System prompt (cite sources, never invent fees or deadlines, hand off legal/tax) |
| `app.py`, `ask.py` | Chat UI and command-line front ends |
| `data/eval/eval_set.jsonl` | The 206-question Phase 2 evaluation set (`seed_questions.jsonl` is the original 10) |
| `build_eval_set.py` | Generates the evaluation set from compact tables |
| `scoring.py`, `evaluate.py`, `compare_runs.py` | Rubric, evaluation runner and run-to-run comparison |
| `tests/` | Offline tests: `pytest -q` (no Ollama or internet needed) |
| `config.py` | Every setting, overridable with environment variables |

## Phase 2: evaluation

`data/eval/eval_set.jsonl` holds 206 questions, generated by `build_eval_set.py` from what the
downloaded pages actually say (edit that file and re-run it to change the set). Categories:

| Category | Qty | What a good answer does |
|---|---|---|
| `fact`, `phrasing` | 86 | States the fact (fee, threshold, program) with a [n] citation from the right page; includes casual and misspelled wording |
| `process` | 12 | Covers every step of a multi-part question (e.g. bakery launch) |
| `followup` | 15 | Uses the earlier turn ("How much does that cost?") and answers the last message |
| `not_in_kb` | 35 | In scope but not in the pages (minimum wage, WSIB...): says it has no official source, no invented specifics |
| `off_topic` | 20 | Politely declines, shows no sources, does not answer (no "Paris") |
| `risky_advice` | 20 | Gives information but sends the person to a lawyer / accountant / the CRA |
| `false_premise` | 18 | Corrects a wrong assumption ("insurance is mandatory, right?") instead of agreeing |

**Rubric.** Each answer is checked by rules (`scoring.py`): the expected facts are present, it cites
[n] at a source that was actually shown, a page that really contains the facts was shown, every
dollar amount / percentage in the answer appears in the sources shown, no forbidden text appears (a
wrong claim or a leaked off-topic answer), and declines/no-source/referral wording is right for the
category. A question passes when all of these rule checks pass. A local-model judge also scores
*faithfulness* 1-5 and *helpfulness* 1-5, but only as a screen for you to spot-check answers by
hand (see the note below) - it does not decide pass/fail.

```bash
python evaluate.py --per-category 3    # balanced smoke test: 3 questions from each of the 8 categories
python evaluate.py                       # full run, 206 questions (roughly 45-75 minutes with the judge)
python evaluate.py --no-judge            # rule checks only, about half the time
python evaluate.py --rescore data/eval/runs/<folder>   # re-apply the current scoring rules to saved answers (no model calls)
CHAT_MODEL=llama3.2:3b python evaluate.py --sample 60      # compare another model on the same 60
python compare_runs.py data/eval/runs/<older> data/eval/runs/<newer>
```

Each run writes `data/eval/runs/<time>_<model>/summary.md` (pass rate by category and the
most common failure reasons), `results.csv` (open in a spreadsheet; fill the `MY_GRADE_1to5`
column for a sample to check the scoring) and `results.jsonl`. Runs can be interrupted and continued
with `--resume <run folder>`.

**Pass/fail comes only from the rule checks** (facts present, cites `[n]`, cites the right page,
citation numbers actually exist, no forbidden claim, and - for `answer`/`refer_professional`
questions - every dollar amount or percentage in the answer appears somewhere in the sources shown,
`numbers_supported`). The local-model judge (faithfulness/helpfulness, `judge_faithful` in the CSV)
is informational only: across two full runs it flagged several correct answers as unfaithful while
missing a real invented figure (the model said a loan program lent "up to $45,000" when the source
caps it at $15,000 - `numbers_supported` catches that kind of thing, the judge didn't). `summary.md`
has a "Judge flagged, but passed" section listing low-faithfulness answers for you to spot-check by
hand; `numbers_supported` only runs on a fresh `python evaluate.py`, not on `--rescore`, because
`results.jsonl` doesn't save each source's full text (only title/url/similarity).

**Working method:** run once for a baseline, change ONE thing (prompt, model, `MIN_SIMILARITY`,
`TOP_K`, a new source page), run again, and use `compare_runs.py` to see what got better or worse.

## Content licensing (read before sharing this publicly)

- **Ontario pages** (`ogl_ontario`): Open Government Licence - Ontario allows commercial use
  with attribution. The app footer already carries the required statement.
- **Canada.ca pages** (`crown_noncommercial`): Government of Canada terms allow reproduction
  without permission for **non-commercial** use only, with the title, author and source URL
  cited. Fine for a personal prototype. Get written permission (or drop these pages with
  `python fetch_sources.py --license ogl_ontario`) before offering a commercial product.

## Things to tune once it runs

- `MIN_SIMILARITY` (default 0.52): raise it if answers cite irrelevant passages, lower it if
  the assistant too often says it found nothing. (On-topic questions scored 0.57-0.83 and an
  off-topic one about 0.50 in first tests.)
- `TOP_K`, `CHUNK_CHARS`, `MAX_SOURCE_CHARS`: more context helps a larger model but can confuse a small one.
- `KEYWORD_SEARCH` (default 1): set `KEYWORD_SEARCH=0` to turn the keyword search off, for comparing runs.
  It only fires when a rare word from the question (one in at most 3 chunks) appears in a chunk that
  also covers most of the question's other words, and its hits score `LEX_SIMILARITY` (0.60), below
  `SCOPE_CHECK_BELOW`, so they still pass the scope check.
- `FULL_PAGE_MAX_CHARS` (4500) / `MAX_TOTAL_SOURCE_CHARS` (10000): pages this short are sent to the model
  whole (so it sees complete lists) as long as the total stays under the budget; longer pages fall back
  to the best chunks (`MAX_SOURCE_CHARS` each). Lower the budget if you raise the chat model's size
  requirements or see truncation; raise `NUM_CTX` if you raise it.
- `NUM_CTX` (default 8192): Ollama's own default (4096) silently cuts the start of long prompts.
  Lower it if your Mac runs short of memory.
- `CHAT_MODEL`: compare a few models on `data/eval/seed_questions.jsonl` by eye.

## Troubleshooting

- *"Could not reach the local model"*: Ollama is not running (`ollama serve`) or a model was not pulled.
- *"No documents found"*: run `fetch_sources.py`, or add files to `data/my_docs/`.
- *Answers ignore the sources*: use a larger model, or lower `TOP_K`.
- Changed documents or chunk settings? Re-run `python ingest.py` (it rebuilds the database).

## Status of this build

Tested offline: HTML-to-Markdown extraction on sample HTML, heading-aware chunking, vector
storage and retrieval, similarity cut-off, follow-up retrieval, and prompt assembly (43 tests).
Verified on a real machine: page downloads, Ollama embeddings and answers, and the chat UI
(bakery, HST, off-topic and follow-up questions). Known limits: the knowledge base only covers
general start-up pages (no food-premises, municipal or sector-specific rules yet), and small
models sometimes skip inline citations or pad answers, which is what Phase 2 evaluation measures.
